# Changelog

## 1.13.0
- Added Nano Banana 2.1 (Google, released Oct 2026) as a recommended model on all three providers: `nano-banana-2-1` (fal, no suffix), `nano-banana-2-1-higgsfield` and `nano-banana-2-1-nim`, matching the existing no-suffix/`-higgsfield`/`-nim` naming convention. Output aspect ratio matches the input automatically on fal and Nim (both honor `"auto"`, verified live); Higgsfield's NB2.1 fails outright on `"auto"` (confirmed live, auto-refunded both times it was tried) so it's given its own explicit aspect-ratio list and snaps to the closest real ratio instead, reusing the same snapping mechanism already built for Nim's GPT Image models (now generalized to any provider via `aspect_ratio_opts`, rather than Nim-specific). Pricing verified live per provider (fal's published per-resolution rates; Higgsfield via real test generations and credit-diffing; Nim via its free cost-preflight check). Also fixed GPT Image 2.5 Flare/Sunburst · Nim, whose Quality dropdown was wired up correctly on the backend but invisible in the browser (wrong "kind" hid the control) — found while re-checking every model's dropdown visibility for this change, not previously reported. (Filip Filyov)
- Fix: the per-image Character checkbox could silently fail to apply when toggled right before Rewrite/Enhance/Angles — a request already in flight could read the character state before the checkbox's own save landed. Rewrite/Enhance/Angles now carry the checkbox's live state with the same request instead of depending on that race. Added a scroll-to-top button for long image grids. (Filip Filyov)
- Added a lightbox for the character reference thumbnail: click it to view the reference image full-size (closes on click or Escape); click the empty "No character" placeholder to go straight to the upload dialog, the same as clicking Upload. (Filip Filyov)
- Fix: a content-filter refusal on any model (not just Seedance) showed "Seedance refused the input images: its content filter flags realistic people" — leftover wording from when Seedance's video filter was the only thing that ever hit this error path. Now only shown for an actual Seedance refusal; every other model gets an honest message instead, since this is confirmed not to be a reliable "real people" signal (reproduced live: the same Nano Banana 2.1 source images that got refused once passed cleanly on a retry with a similar prompt). Also improved Higgsfield's generic "Server returned an error response" (a transport-layer fallback with no real detail, confirmed traced to the `mcp` package itself) with actionable guidance instead of the bare, unhelpful string. Added a short disclaimer under the Model selector for all three Nano Banana 2.1 entries noting it's newly released and that a refusal or an off-prompt result is worth a retry or a reworded prompt. (Filip Filyov)

## 1.12.2
- Fix: the exe build failed in CI (and would fail locally too) — `--collect-all mcp` makes PyInstaller import every submodule under `mcp` to discover hidden imports, including `mcp.cli.cli`, which unconditionally imports `typer`. RenderPost never uses `mcp`'s CLI (only `ClientSession`/`client.streamable_http`), but `typer` wasn't installed, so that import crashed the whole build before it could produce an exe. Added `typer` to `requirements.txt` — confirmed fixed with a real local `build.bat`-equivalent build and a working `RenderPost.exe` launched afterward. (Filip Filyov)

## 1.12.1
- Fix: GPT Image 2.5 Flare/Sunburst via Nim.video always came back 16:9 regardless of the source image's own aspect ratio — Nim defaults to a flat 16:9 whenever `requestedAspectRatio` is simply omitted, which every Nim image model did until now. Now sends the source's real aspect ratio when it's one of Nim's supported values, or the closest one when it isn't (a new `_nearest_ratio()` helper); Nano Banana Pro Edit/2 use Nim's own `"auto"` option instead, which matches the input directly. Higgsfield and fal were never affected — found live, not something those paths needed. (Filip Filyov)

## 1.12.0
- Fix: enhancing through a Nim.video image model could report "fal refused this request (403)" even though the generation had actually succeeded (visible in Nim's own web UI) — the real failure was downloading the result, from a plain request with no User-Agent header, which Nim's CDN rejects (Higgsfield's own result URLs don't filter on this, so it never surfaced there). GPT Image 2.5 Flare/Sunburst via Nim now have a real Quality selector (Low/Medium/High, each a separate model on Nim's side — fixed to Medium before this), using two new generic engine mechanisms also usable by any future provider: a quality/resolution tier that's really a separate model id (`quality_model_ids`/`res_model_ids`), and a per-model Quality dropdown restriction (`quality_opts`, mirroring the existing per-model Duration restriction) so a model with fewer real tiers than fal's own doesn't silently collapse extra options onto one. Added Nano Banana 2, Kling 3.0, MiniMax H3 and Veo 3.1 as new Nim-routed models, parameters and per-tier pricing verified live via Nim's own model catalog and its free cost-preflight check (no generation needed to verify a price); Seedance 2.5 · Nim gained its full 480p/720p/1080p resolution range the same way, previously fixed to 720p only pending exactly this check. (Filip Filyov)

## 1.11.0
- Nim.video added as a second built-in aggregator provider, alongside Higgsfield: "Nano Banana Pro Edit" and "GPT Image 2.5 Flare" (image), "Hailuo 2.3 Fast" and "Seedance 2.5" (video), connected the same one-time way as Higgsfield and billed on Nim.video credits instead of a separate fal balance. Nim needed two genuinely new engine primitives (now available to any future provider, not just Nim): a two-phase upload step for providers with no import-by-URL tool (mint a short-lived upload slot via an MCP tool call, then POST the file bytes directly), and a flat-array conditional reference item (`"_scalar"`) for providers whose reference list is plain URL strings rather than Higgsfield's role-tagged objects. Also extended the MCP poll-step mechanism to accept a list of terminal values, since Nim's own generation-status tool reaches one of four terminal strings rather than a single done flag. Every model parameter, price and upload mechanic was verified live against Nim's own MCP tools before shipping; "Seedance 2.5 · Nim" is the one exception — its parameters are verified against Nim's live model catalog but it hasn't been run through an actual paid generation, and its resolution is fixed to the one tier whose price was confirmed (720p) until someone does. (Filip Filyov)

## 1.10.0
- Image/video generation (never prompt-writing or vision analysis, which stay on fal) can be routed to a third-party aggregator instead of fal.ai, chosen per model in the existing Model/Video model dropdowns. New "Connect providers" settings panel handles per-provider API-key or one-time OAuth connect (Dynamic Client Registration where a provider supports it — no manual app registration needed); headless afterward, with silent token refresh. Providers are declarative catalog entries, added via the model catalog JSON or pasted as a custom provider (now with setup instructions in that panel); Higgsfield ships as a built-in entry (Flare/Sunburst/Seedance, paired against their fal counterparts, billed on your Higgsfield subscription instead of a separate balance) — Artlist/Nim.video to follow the same way. Fixed a race in config.json's own save path (unrelated autosaves could clobber a just-connected/disconnected provider) and a gap where a character reference was never passed through to an aggregator. (Filip Filyov)
- Added Nano Banana Pro and Nano Banana 2 as Higgsfield-routed image models, paired against their fal counterparts. GPT Image 2.5 via Higgsfield gains its own Quality selector (previously fixed to Medium); a new "gptres" model kind drives Quality + Resolution together, and the per-image spend estimate now uses a verified quality-by-resolution price table instead of a flat rate. Added Kling 3.0 Pro, MiniMax H3 and Veo 3.1 as new Higgsfield-only video models (no fal equivalent shipped for these), each fixed to a predictable, verified parameter set (mode/sound/quality tier) so spend stays a flat rate per second; Veo 3.1's duration selector is limited to the 4s/6s/8s values it actually accepts. All new model parameter names, options and per-model pricing were verified live against Higgsfield's model catalog and cost-preflight tool, not assumed. (Filip Filyov)
- Fix: a Higgsfield video/image generation could fail with an opaque "unhandled errors in a TaskGroup" error that hid the real cause. Found live with Kling 3.0 Pro: Higgsfield's batch tools can intercept a literal submission with "a preset was recommended instead" rather than submitting it — now auto-declined and resubmitted once, transparently. Also unwrapped the TaskGroup wrapper itself so any other underlying error (a real 401, a timeout, ...) shows its actual message instead of the generic wrapper text. (Filip Filyov)
- Fix: Kling 3.0 and Veo 3.1 via Higgsfield shipped with no Resolution control — both were fixed to a single hardcoded tier (Kling always "Pro", Veo always "Basic") even though each has a real, cost-varying quality tier at the API level (Kling's "mode": std/pro/4k; Veo's "quality": basic/high/ultra). Renamed "Kling 3.0 Pro" to "Kling 3.0" and gave both models a proper Resolution dropdown driving their real tier parameter, each verified against its real per-tier cost. MiniMax H3 still has no Resolution control — verified it genuinely only offers one resolution ("2K") at the API level, so there is nothing to select. (Filip Filyov)
- Added Gemini Omni Flash 1.1, Grok Imagine 1.5, Happy Horse Video and MiniMax Hailuo 2.3 as new Higgsfield-only video models, with resolution/duration options verified against each model's real schema and per-tier pricing verified live. ("Flux.3" was also requested but does not exist in Higgsfield's current catalog — not added.) Hardened the MCP call path generally: a failing call now retries up to 3 times with backoff before giving up (matching the retry pattern already used for REST calls elsewhere), and failures are now logged with their real underlying cause for diagnosis. Known issue: these four new models currently fail consistently when generated through the app (reproduced across multiple source images and both AI-written and hand-written prompts), while an identical request against Higgsfield's API directly succeeds — most likely an account/plan entitlement gap rather than a bug in these settings, but not fully isolated. Kling 3.0, Veo 3.1, MiniMax H3 and Seedance 2.5 are unaffected and continue to work normally. (Filip Filyov)
- Removed Gemini Omni Flash 1.1, Grok Imagine 1.5, Happy Horse Video, MiniMax Hailuo 2.3 and FLUX.3 Video (added above; FLUX.3 Video was in fact found and added in a follow-up commit, correcting the "does not exist" note) at Filip's request. A direct test through a second, independent MCP client (bypassing RenderPost entirely, logged in `higgsfield-mcp-log.md`) showed all five work at least intermittently on Higgsfield's own platform, which rules out a RenderPost bug or an account/plan gap as the explanation for the failures above — but the inconsistency itself (two of five fail on roughly half of attempts, confirmed by Higgsfield's own auto-refunds) made them not worth shipping for now. Kling 3.0, Veo 3.1, MiniMax H3, Seedance 2.5 and the rest of the Higgsfield lineup are unaffected. (Filip Filyov)
- Seedance 2.5 · Higgsfield and MiniMax H3 · Higgsfield now attach the character reference image as a second input when generating a clip from a version that was itself generated with character reference on — the start frame stays the first reference, the character image is added as a second ("image_references") reference, matching the input shape Filip verified working in Higgsfield's own web UI. Scoped to clip generation only (not takes, which already attach the character a different way) and to these two models only; every other video model is unaffected. (Filip Filyov)
- Simplified the above: inferring character presence from the picked version's own generation history was too indirect and broke for images generated before that history existed. Replaced with an explicit "Reference character" checkbox on the clip card, shown only for these two models when a character is present — independent of how the picked frame was itself generated. (Filip Filyov)
- Fix: MiniMax H3 with character reference on failed every time with a 422 ("start_image/end_image cannot be mixed with reference media") — its real API, unlike Seedance 2.5, rejects a start frame and a reference image together; both have to go in as reference images, frame first. Confirmed live via a direct MCP test before fixing. Seedance 2.5 is unaffected — its combination still works as before. (Filip Filyov)
